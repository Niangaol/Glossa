# Glossa Studio：可交互代码工作台（设计 v1）

日期：2026-11-17 · 状态：待批准 · 用户拍板：单文件离线 · 双层下钻 · 事实面板 · 工作台专用深色 · 子系统按顶层目录聚合

## 0. 一句话

把 `glossa explain` 的静态阅读页换成**可交互的工作台**：中间一张能缩放、能点、能下钻的流程图，左侧工具轨道，右侧详情面板；输出仍是**一个 HTML 文件**，双击即用，零外链零构建。

## 1. 为什么是新渲染路径

- `explain.html` 是全静态、`<script>` 计数为 0 的阅读页（三套风格），交互必须要有 JS，所以 studio 是并列的第二条产线，替换不了它，也不受它的 style 词汇表约束。
- 数据不用重新扫：`repo.json` 里已有 graph（nodes/edges/layers/cycles/unreachable/truncated）、每个文件的 symbols/imports/parse/degraded、packages/projects/entries。studio 只做**取数 → 聚合 → 算坐标 → 内联 → 渲染**。

## 2. 两层视图

| 层 | 节点 | 边 | 进入方式 |
|---|---|---|---|
| 全景（默认） | 子系统（顶层目录聚合，≥2 个文件才成组；其余进「散件」组） | 子系统之间的聚合依赖（跨组 import 计数） | 打开即是 |
| 文件层 | 组内文件节点 | 组内 file 级 import 边 | 双击子系统 / 面包屑返回 |

子系统聚合规则（程序算，不靠 AI）：取 `files[i].path` 的第一段目录；第一段没有目录的文件进 `<root>` 组；`node_modules/`、`.git/` 这类已被 scan 剪枝，不会出现。组名默认就是目录名，**不翻译**。

AI 只做两件可选的装饰：给组起中文名（≤8 字）、写一句话说明（≤40 字）。没配模型时用目录名与「N 个文件 · M 个符号 · K 条依赖」的事实句，绝不留空。

## 3. 界面结构

```
┌──────────────────────────── bar ─────────────────────────────┐
│ 笺疏 Studio · safetrace   485 文件 1,019 符号 · 未溯源 2 处    │
├────┬───────────────────────────────────────────┬─────────────┤
│ 轨 │ 画布                                       │ 详情面板     │
│ 道 │  [ 子系统卡片 ]──▶[ 子系统卡片 ]           │ 事实卡       │
│    │        │                  │                 │ 依赖列表     │
│    │        ▼                  ▼                 │ 降级原因     │
│    │  [ 子系统卡片 ]──▶[ 子系统卡片 ]           │ 源码片段     │
├────┴───────────────────────────────────────────┴─────────────┤
│ 面包屑：全景 › src/ingest        提示：双击下钻 · 空格拖动 · +/- 缩放 │
└──────────────────────────────────────────────────────────────┘
```

- **左轨道**（56px 图标 + 悬停文字）：视图切换（全景/文件）、图层亮度、只看入口可达、只看有降级、搜索。
- **画布**：一个 `<svg>`，`<g id="viewport">` 承载 pan/zoom 变换；节点是 `<g class="node">`（圆角矩形 + 标题 + 两行事实），边是 `<path>` 带箭头 marker。所有坐标由 Python 算好写进数据，JS 只做变换与状态，不做自动布局（重排会让同一个仓库两次生成的位置不同）。
- **详情面板**（320px，可折叠）：标题与路径、四格事实（文件/符号/依赖/行数）、依赖与被依赖列表（可点跳转）、降级原因（原样给，不美化）、源码片段（前 80 行，可展开到 200 行）、复制路径按钮。
- **面包屑**：`全景 › <组名>`，点「全景」返回；`Esc` 等价。

## 4. 交互清单（都要能测）

| 行为 | 触发 | 断言点 |
|---|---|---|
| 选中节点 | 点击 / Tab+Enter | `g.node.is-selected` 唯一，面板标题等于节点名 |
| 下钻 | 双击子系统 / 面板「进入」 | SVG 里只剩该组文件节点，面包屑出现组名 |
| 返回 | 面包屑「全景」/ Esc | 回到子系统层，选中恢复 |
| 缩放 | 滚轮 / `+` `-` / 双指 | `viewport` 的 `scale` 在 0.25–3.0，右下角显示百分比 |
| 平移 | 拖动空白 / 空格+拖动 / 中键 | 位移可复位（「适应画布」按钮） |
| 搜索 | 输入 | 命中节点加 `.is-hit`，其余降到 0.25 透明；`Enter` 选中第一个 |
| 图层 | 只看入口可达 | 不可达节点降到 0.2 并计数显示 |
| 键盘 | `1` 全景 `2` 文件 `f` 适应画布 | 与按钮同效 |

## 6. 产物与预算

- 命令：`python -m glossa studio --repo <路径> --out <目录> [--ai] [--force]`，产物 `studio.html`（+ 复用 `repo.json`）。
- 体积：单文件 ≤ 2.5 MB（数据内联、gzip 不用）。超限时按顺序砍：源码片段 → 文件层节点数 → 子系统数，并在页脚写明砍了什么、原有多少。
- 节点上限：子系统 ≤ 80、文件层每组 ≤ 120；超限节点不画，计数进页脚（沿用 R301 的「截断只计数」口径）。
- 仍是零外链：不允许 `<script src>`、`<link>`、`url(http…)`；`xmlns="http://www.w3.org/2000/svg"` 例外。

## 7. 诚实体现在哪里

- 页脚固定披露：统计口径 listing、剪枝目录只计数、截断数与丢弃数、图不是全量。
- 详情面板里 degraded 原样展示，不合并、不缩写。
- 没有入口 / 没有依赖 / 没有符号都写「无」，不写「暂未分析」。

## 11. mock v2 定稿（2026-11-17 实做并截图核对）

SafeTrace 数据实测：11 个子系统，组间边只有 2 条（`scripts` → `src` 130 次、`src` → `scripts` 17 次），其余 9 个目录零跨组依赖。据此定下三条布局规则，避免「有依赖的排一行、没依赖的排一片」看起来像散点：

1. **顶部依赖带**：有跨组依赖的子系统排成一行（按文件数降序），卡片间距 520px 给箭头留空间；正向边是带弧度的横线（两个方向上下错开 20px），回边从卡片下方 52px 绕回，不穿卡片。
2. **分隔线**：`gridTop - 74` 处一条虚线，线下一行小字「以下 N 个目录与任何目录都没有跨组依赖」，再下面是 3 列 × 190px 行距的网格，卡片宽 320 高 152。
3. **卡片信息**：左侧 3px 用途色条（code `#5b9cf6` / test `#48b78f` / config `#f2b134` / docs `#8a94a6` / data `#b07cf0`），标题 14px，副标题写主导扩展名与数量（`255 个 .ts 文件`），中间最多 3 条子项（目录带 `/`、文件不带），页脚分隔线上写文件数 / 符号数 / 降级数（降级用琥珀色）。

文件层（双击下钻）当前实现：按目录分块，块头是目录名 + 文件数，块内 3 列、卡 300×54（文件名 + `语言 · 行数 · 符号数 · 降级数`）；每组最多画 60 个文件，其余在画布标题里写「另有 N 个未画」。进入文件层默认缩放 72%（一屏放不下，可滚轮缩到 25% 看全貌）。

已知仍需在 ST3 里解决：文件层 60 个文件仍要用户缩放才读得清；边在文件层默认 30% 透明度，只在与选中节点相连时点亮。这两条不改结构，只调布局与样式。

## 12. mock v3 定稿：三层 + 深浅主题 + 动效（2026-11-17，用户 m15646 三条追加要求）

> 本节取代 §2 的「两层视图」。用户原话：「我想要配色适配设备的深色浅色主题，然后分层级，第一层展示总的系统架构，双击某一个子系统展示子系统的架构，动态元素多一点」。原型：`docs/studio/mock/index3.html`（单文件，离线可开，随仓库发布）；截图 `01-system-dark.png` … `06-files-light.png` 是本地施工产物（`docs/studio/shots/`，13MB，未随仓库发布）。

### 12.1 三层结构

| 层 | level | 节点 | 边 | 进 | 出 |
|---|---|---|---|---|---|
| 系统层 | `group` | 顶层目录（11 个） | 目录间 import 聚合 | 默认 | — |
| 子系统层 | `sub` | 该目录的**下一级目录**（如 `src` → qa / ingest / gateway / assets / enrich / shared） | 文件级 import 按模块聚合，≥4 次才标 ×N | 双击卡片 | Esc / 面包屑「全景」 |
| 文件层 | `files` | 该模块的文件（按目录分块） | 文件级 import | 双击模块卡片 | Esc / 面包屑「子系统」 |

- 状态机：`{level, group, module, sel, scale, tx, ty, q, onlyDegraded, theme}`；数字键 1/2/3 直接跳层，面包屑三级可点，`canvas-head` 标题随层变化（「qa/的文件 · 14 个文件」）。
- 模块卡片：标题 = 模块名，副标题 = 主导扩展名统计，第三行 = `prefix`（真实相对路径，如 `src/qa`），页脚 = 文件数 / 符号数 / 降级数；用途色条与系统层同一套。
- 文件层过滤口径：`dir === prefix` 精确匹配（root_bucket 即本目录直属文件），否则 `dir === prefix || dir.startsWith(prefix + "/")`。模块内文件全画，仅当超过 60 才截断并写「另有 N 个未画」。

### 12.2 深浅主题

- 默认 `color-scheme: dark light` 跟随系统：深色为默认令牌，浅色走 `@media (prefers-color-scheme: light) { :root:not([data-theme="dark"]) { ... } }`；手动覆盖走 `[data-theme="light"]` / `[data-theme="dark"]` 双保险（媒体查询 + 属性选择器同时满足）。
- 顶栏按钮循环 auto → light → dark，写 `document.documentElement.dataset.theme`；图标同一枚（太阳/齿轮），title 说明当前档。
- 令牌（深 / 浅）：bg `#0e1116` / `#f5f3ee`；panel `#141a21` / `#fffdf9`；line `#232c36` / `#ded7ca`；ink `#dfe6ee` / `#1f242b`；ink-2 `#9aa7b6` / `#5d6672`；ink-3 `#6b7886` / `#8a8f96`；azure `#4f8ef0` / `#2f6fd0`；amber `#e0a83a` / `#a8750c`；mint `#3fae86` / `#2b8365`。
- 浅色下卡片必须给投影（`filter: drop-shadow(0 1px 2px rgba(60,50,30,.10))`，悬浮加到 `0 8px 18px`），否则白卡贴米白底读不出层级。

### 12.3 动效清单（全部在 `prefers-reduced-motion: reduce` 下关闭）

1. 节点入场：`nodeIn .42s`，每卡延迟 `--i * 26ms`（最多 40 档），opacity 0→1 + translateY 6px→0。
2. 选中边：`stroke-dasharray: 6 5` + `flow .85s linear infinite`（`stroke-dashoffset → -22`），即蚂蚁线。
3. 选中卡：卡片外圈脉冲环 `pulse 1.8s`。
4. 镜头：切换层级/适应画布走 rAF 缓动 `1-(1-k)^3`，420–460ms；位移与缩放同时插值，避免瞬移。
5. 侧栏：换选中节点时 `.scroll` 重新挂 `fadeUp .26s`。
6. 顶部统计：进入页面 700ms 数字滚动到位（`data-n` 目标值）。
7. 悬浮：卡片抬升 + 描边变亮（`transition .18s`）。

### 12.4 布局与路由（v3 修正）

- 系统层：依赖带 pitch 520，网格 3 列 × 190px，分隔线在 `gridTop - 74`。
- 子系统层：3 列网格，列距 384 / 行距 210，卡片 320×152；边走「右缘 → 左缘」贝塞尔，回边（目标在左）绕卡片下方 52px。
- 文件层：3 列，卡 300×54，行距 108，目录块头在块首行上方 22px；边走**总线**（起点卡片底 → 车道 `bottom + 34 + i*9` → 终点卡片底），默认 26% 透明度，只在与选中节点相连时点亮。
- `fit()`：留白 56；系统层垂直居中并**额外预留底部 42px 给图例**（否则最后一行被图例压住）；子系统/文件层顶对齐 78px。下钻后必须重算 fit，不要写死初始相机。

### 12.5 mock 期踩到的四个坑（ST1 落实现时必须继承）

1. 每个节点分组必须写 `transform="translate(x,y)"`，否则所有卡片叠在原点（表象：只看到最后一个节点）。
2. 文件层节点必须带 `dir` 字段；缺了按模块过滤会得到 0 个文件（表象：标题写「14 个文件」但画布空白）。
3. 文件挑选必须**按目录轮转**（`per_dir` 轮询到 60 个），不能 `paths[:120]` 截断——实测截断后 `src/qa` 一个文件都进不来。
4. 下钻到文件层不能写死相机（`zoomTo(0.72, 24, 46)`），坐标是组内绝对坐标，必须按当前可见节点重算 `fit()`。

## 13. v3.1 改版：从「整齐网格」改成「数据流」（2026-11-17，用户 m15840）

> 用户原话：「中间的线不够明显 然后排版太规整了，能不能更凸显数据流向 不用这么整齐」。v3 的 3 列网格被整体废掉，三层全部改成力导向。

### 13.1 布局：力导向 + 依赖层播种

- 三层共用 `docs/studio/mock/` 生成脚本里的 `force_layout()`：斥力（`k²/d`，带 `2.6k` 截断）+ 边弹簧（`d²/k × log(1+count)`）+ 弱向心力 + 边界盒裁剪，跑 600–760 轮。
- **初始位置不是随机的**：按 `longest_layers` 算出的依赖层播种，第 0 层在左、逐层往右（`lay * 330/360`），同层向下堆；再加 `_u(crc32(key))` 的确定性抖动。同一份 repo.json 每次跑出来的图完全一致（可截图对比、可做快照测试）。
- 画布盒子：系统层 `1100×640`、子系统层 `1180×760`、文件层 `1520×1180`；跑完力导向再 `relax_overlaps()` 做矩形去重叠（按穿透更浅的轴推开），最后 `to_cards()` 平移到正坐标。
- 卡片尺寸随内容变：系统层 `312 + 24×min(4, files//70)`，子系统层 `300 + 26×min(3, files//10)`，文件层固定 `296×54`。**边和 fit 都必须用节点自带的 w/h**，不能再用层级的固定常量。

### 13.2 边：从「灰色细线」改成「有方向的流」

- 颜色：一律主色 `--azure`，不再用 `ink-3` 灰；底层再叠一条 `stroke-width + 6px`、`blur(2.4px)`、透明度 12% 的**光晕**，让线从卡片堆里浮出来。
- 动画：`stroke-dasharray: 9 7` + `flow 1.7s linear infinite`（`stroke-dashoffset→-30`），选中时加速到 0.8s、透明度 100%。**箭头必须 `markerUnits="userSpaceOnUse"`、11px**——用默认的 `strokeWidth` 单位时，线宽 4px 的边会把箭头放大成巨大的蓝三角（v3.1 第一版就踩了这个）。
- 粗细：`1.2 + 1.35 × ln(1 + count)`，上限 5.4px；`count>1` 在中点标 `×N`，标签加 `paint-order: stroke` + 背景色描边，压在线上也读得清。
- 走线：卡片**边界锚点**之间的三次贝塞尔，中点沿法线鼓出 38px（文件层 22px）；鼓的方向由 `a.id < b.id` 决定，所以 A→B 与 B→A 必然弯向两侧，不会叠成一条。
- 流向感：最重的 14 条边挂 `<circle class="packet">` + `animateMotion`/`mpath`，光点沿着路径循环跑（SMIL，离线可用，不依赖 JS 定时器）。
- 文件层的边自动降级：`i < 14` 之外不发光点，透明度用 `.edge.dim` 压到 12%，只在与选中节点相连时点亮。

### 13.3 诚实性没有丢

- 文件：有 `doc_first_line`（真注释）就用；否则「角色词 + 前 3 个符号名 + 符号数 + 类型」，例如「采集：CVEORG_SOURCE_ID、CVEORG_RELIABILITY、pa… 3 个常量」；没解析出符号的写「这个文件没有符号（解析降级）」。

## 15. 箭头重做 + 简介接模型（v3.3）

### 15.1 用户原话与根因

用户 m15996：「数据传输的箭头非常不明显 重做!」查下来是三个叠加的错：

1. **`--green` 这个 CSS 变量从来没定义过**。`:root` 里只有 `--azure/--amber/--mint/--rose`，而 `.edge.dat`、`.packet.dat`、`.edge-label.dat`、`.arrowtip.dat`、`.legend i.dat` 全写的是 `var(--green)`——无效变量在计算值阶段失效，颜色全靠继承碰运气。
2. **箭头被卡片压住**。原来全靠 SVG `marker-end`，路径终点正好落在卡片边框上，而节点组（`gN`）在边组（`gE`）之后 append，箭头永远在卡片下面；11px 的 marker 相对 320px 的卡片也太小。
3. **marker 的缩放单位**。默认 `markerUnits="strokeWidth"` 会把箭头按线宽放大，改线宽时箭头大小跟着乱跳。

### 15.2 改法

- 补 `--green: #46c98f`（深色）/ `#1c7a52`（浅色），所有 `var(--green)` 加兜底值。
- **箭头自己画，不用 marker**：`edgeGeom` 额外返回终点 `p1` 与控制点 `c2`，切线方向 = `p1 - c2` 归一化；尖端放在**卡片外侧**（数据流 7px、依赖 4px），尺寸 `16 + min(9, 2.2·weight)`（依赖 `10 + min(5, 1.2·weight)`）。
- 箭头收集进 `arrowTops`，节点画完后单独 append 一个 `g.arrowtops` 层（在 `gN` 之后），**所以箭头永远压在卡片之上**；`applyHot()` 里也按 `state.sel` 切换 `.arrowtip.live`。
- 落点分散：`spread = ((i % 7) - 3) * 15`，把瞄准点沿法线平移再求边界交点，避免一簇箭头叠成三角团。
- 数据流线宽抬到 `2.6 + min(4.2, 1.9·ln(1+c))`、依赖压到 `1.0 + min(2.4, 0.9·ln(1+c))`，透明度依赖 .22 / 数据流 1。

## 16. 纸质主题（v3.4）：把界面做成一张案头纸

### 16.1 为什么是纸，而不是又一套深色 HUD

用户要「纸质材质和质感」。这不是换皮，是把视觉语言从题材里长出来：这是给工程师看的**代码导览稿**，最贴切的原型就是案头的一叠稿纸——格子纸做底、纸片做卡片、铅笔线画依赖、朱笔标流向。同时也解决两个实际问题：墨字压纸对比高、久看不累；纸的层级（叠、压、批注）天然对应「系统 → 子系统 → 文件」。

原则性避开：不要通用霓虹/HUD 皮肤，不用玻璃拟态，不用大圆角发光。

### 16.2 令牌（三处主题块必须同步改）

| 令牌 | 日读（浅） | 夜读（深） |
|---|---|---|
| 纸底 --bg | #efe7d6 米白稿纸 | #17140f 暖炭纸 |
| 卡片 --paper | #fbf6e8 | #221e17 |
| 墨字 --ink | #2c2823 | #e9dfc9 |
| 朱砂 --flow（数据流） | #b0402f | #d4745c |
| 墨蓝 --azure（import 依赖） | #3f5f8a | #7f9cc4 |
| 界栏 --line | #d6c8ae | #362f25 |
| 印章 --seal | #b8402f | #b8402f |

语义落位：**朱笔 = 数据流**（谁把数据喂给谁，要一眼看见），**铅笔虚线 = import 依赖**（背景信息，可以退后）。选中态用朱批（stroke 换 --flow），不再是浏览器蓝。

### 16.3 质感四件套

1. **纸纹**：`.stage::after` 铺一张内联 SVG 颗粒（feTurbulence + feColorMatrix 去色），`mix-blend-mode: multiply`、`opacity: var(--grain)`（浅 .34 / 深 .30）。因为叠在整张画布之上（z-index 3），卡片和底纸是同一层颗粒，看起来才像同一张纸。
2. **纤维**：`body::before` 两组 `repeating-linear-gradient`（94deg 与 -87deg），1px 间隔、极低不透明度，消除大面积纯色的塑料感。
3. **暗角**：`.stage` 加 `box-shadow: inset 0 0 140px -50px rgba(70,52,30,.40)`，像一张铺在桌上的纸边缘略暗。
4. **格纸**：24px 方格用两条 `linear-gradient` 叠成（不是印刷网点），浅到只在空白处可见。

### 16.4 纸片与纸叠纸

- 每张卡后面多画一张 `rect.sheet`，向右下偏移 3 / 4.5px、`fill: color-mix(in srgb, var(--bg) 86%, var(--ink))`——纸叠纸的厚度，层级感来自这里，不靠发光边框。
- **按用途分色纸**：`g.node[data-role]` 决定卡片纸色（code 米白 / test 淡青绿 / config 淡赭 / docs 灰米 / data 淡紫 / other 米黄）；深色主题给对应的暗色纸。左侧 3.5px 色条同步换成墨色调（ROLE 从霓虹 #4f8ef0 系改成 #4a6b96 / #4a7a5f / #a8762a / #8d8577 / #7a5f93）。
- 字体分工：标题/卡片名/右栏 h1 用**衬线**（Songti SC → Noto Serif SC → SimSun，finally Georgia），路径、数字、代码用等宽。中文衬线在小字号下比黑体更像印刷稿。
- 品牌位做成**朱印**：26×26 红章写「笺」，-2.5deg 微旋，内描边模拟压印。

### 16.5 顺带修掉的箭头重叠

上一版用 `spread = ((i%7)-3)*15` 均匀分散，仍有 2–3 个箭头叠在一张卡的边缘。改成**落点占位**（`pickArrowSlot`）：每张卡记录已占用的落点，候选 spread 依次为 0/±18/±36/±54/±72，取「离已有落点最远」且 >24px 的那个；找不到就退到最远候选。箭头尺寸同步收一档（数据流 `14 + min(8, 2.0·weight)`，依赖 `9 + min(4, 1.1·weight)`），因为朱砂本身就比绿色更抢眼。

### 16.6 踩到的坑

- 颗粒层 `z-index: 3` 会盖住图例和缩放条（它们原本没有 z-index）→ 浮层统一 `z-index: 4`。
- 分色纸靠 `data-role`，必须在 `drawGroupCard` / `drawModuleCard` / `drawFileCard` 三处都挂；只挂前两个时文件层全是默认纸色。
- 主题令牌有**三份**：`:root`（深色默认）、`@media (prefers-color-scheme: light)`、`[data-theme="light"]`；新增 `--tint-*` 时漏一处就会出现「跟随系统浅色正常、手动切浅色变黑纸」。
- 纸色不能交易：卡片纸色必须与 `--bg` 保持 4% 以上明度差，否则暗角和颗粒一叠就糊成一片。

## 17. v3.5：朱批动效 + 档案卡索引条（用户选的 C + 少量 B）

### 17.1 这轮只做两件事

用户在「继续打磨细节（C）」和「系统层加一条档案卡索引（B）」里选了 **C + 少量 B**：C 是把「选中」从一根描边变成一次批阅动作（划线 + 盖印），B 是只给系统层的索引条：**文件层必须保持干净**，那里本来就是一行行卡片，再塞一条索引条只会更乱。

### 17.2 朱批两件套

选中一张卡时发生两个动作，按时间顺序：

1. **朱线**（`path.annot`）：标题下方一道微弯的红线，`stroke-dasharray = 全长`、`stroke-dashoffset` 从全长动画到 0（340ms），看起来是有人拿朱笔当场划的。
2. **盖印**（`g.stamp`）：30×30 的红章写「阅」，`stampIn` 关键帧从 `scale(1.9) rotate(-17deg)` 砸到 `scale(1) rotate(-8deg)`，中间在 58% 处回弹到 `.92`——真盖章有个"压下去再弹"的手感。

三个实现细节，缺一个就变形：

- 线的长度用 `getComputedTextLength()` 取**标题实际宽度 × 0.94**，不能用固定值：固定 136px 会横穿 `path`/`fdir` 那行副标题，看起来像划错地方。
- `decorate()` 必须在 `vp.appendChild(gN)` **之后**调用。`getTotalLength()` 对还没进文档的元素会返回 0，线就永远是"已经画完"的状态，动画消失。
- 印章用 `transform-box: fill-box` + `transform-origin: 50% 50%` 才能以自己为中心缩放；SVG 默认原点是画布左上角，不加这两行章会从画面外飞进来。

### 17.3 档案卡索引条

右侧边缘一列 29×25 的纸片标签，每张只写两三个字符（拉丁取前两位 `co`/`sr`，中文取首字 `根`）。系统层才有，进子系统或文件层直接 `display:none`。

- **不做整条展开**：第一版是悬停整条变宽到 178px，11 个目录一起摊开，结果它变成一块盖在画布上的白色面板，正好压住比例最高的 `src` 卡。改成**单个 tab 悬停才变宽**（29px → 168px，露出全名和文件数），一次只让一张纸片抽出来。
- 点一下就 `select()` + `focusNode()`（把相机缓动到这个卡片的中心），等于"从索引里翻到这一页"。
- 容器本身透明无边框，纸片各带自己的 `box-shadow: var(--sheet)`；整条加底板会立刻变成"侧边栏"，纸片各自带阴影才像卡片盒上凸出来的标签。

### 17.4 纸纹从"有"到"摸得到"

上一版颗粒 `opacity .34 / .30` 在 1× 下几乎看不见，只有截图放大才隐约有噪点。这轮：

- 颗粒提到 **.50（浅）/ .44（深）**——再高就吃小字，5px 的等宽数字会开始发毛；
- `body::before` 从两组纤维加到**三组**（94deg / -87deg / 2deg，第三组周期 13px），补上一层"横向慢波"，消除大面积纯色的塑料感。

判据是 5× 放大截图：能看到细密颗粒 + 方格 + 纤维三层，1× 下文字仍然锐利。

### 17.5 这轮踩的坑

- 印章第一版挂在卡片**右上角外侧**（`x = W-26, y = -10`），结果压住了上方邻居卡的页脚（"67 文件"被盖掉一半）。改挂**左上角内侧**（`-13, -13`），只外溢 13px，且标题从 x=16 起不会撞上。
- 索引条第一版整条展开成 178px 面板，既盖住画布又像侧栏（见 17.3），已回退成单 tab 展开。
- 索引条背景直接写 `transparent` 会让纸纹透上来，小字发灰；必须是 `color-mix(in srgb, var(--panel) 94%, transparent)`，让纸片自己有一点"实"的底色。
- 塌陷态只显示一个字会出现两个 `c`（config / contracts）、两个 `s`（scripts / src）无法区分，所以拉丁标签取两位。
